# دوال متوازي — الإعداد والنشر

> **النشر بيدك وحدك.** لا مفتاحٌ حقيقيّ في هذا المستودع.

## الأسرار — تُوضَع من خارج الكود

```bash
firebase functions:secrets:set MOYASAR_SECRET_KEY      # sk_test_... أو sk_live_...
firebase functions:secrets:set MOYASAR_WEBHOOK_TOKEN   # نصٌّ عشوائيّ طويل تختاره أنت
```

تُخزَّن في Google Secret Manager، وتقرؤها الدالّة وقت التشغيل. **لا تضعها في
`functions/.env`**.

**الوضع (اختبار/إنتاج) يحدّده المفتاح وحده.** مفتاحٌ يحمل `_test_` ⇒ اختبار،
وما عداه ⇒ إنتاج. وحدث ويب-هوك وضعُه مخالفٌ لوضع المفتاح لا يُفعِّل شيئًا.

## إعدادٌ غير سرّي (اختياري)

القيم الافتراضية تكفي. وللتغيير: `functions/.env`

```
SITE_ORIGIN=https://motawazi.com
```

## الاستمارة الصحية — `submitIntake`

المتصفح يرسل `{ answers }` فقط. الدالة: تتحقق (`nutrition.js`) ← تحسب السعرات ←
تفرز ← تكتب `profiles/{uid}` و`weights/{uid}/entries/intake` في معاملة واحدة.
لا تحتاج أي سرّ، فتُنشر مستقلةً عن دوال الدفع.

**إعداد التغذية:** `nutrition.config.json` — كل القيم (معاملات النشاط، العجز،
الحد الأدنى لكل جنس، نسب المغذيات، حدود مؤشر كتلة الجسم، أقل عمر، شاشة ولي الأمر،
حدود الإدخال). إعدادٌ غير صالح يُفشل الاختبارات والنشر. ارفع `version` مع كل تعديل.

## الباقات والأسعار

كلها في `plans.js` — المصدر الوحيد. كل باقة لها `days` و`amount` (بالهللات).
**الباقة التي سعرها `null` لا تُباع**: الدالّة ترفضها بـ«غير متاحة بعد».
لإضافة باقة (مثل ٣ شهور مع الدفتر المطبوع): سطرٌ جديد في `PLANS`، وبطاقةٌ
في `account.html`.

## قبل أول نشر

```bash
cd functions && npm install
node test.js
```

**⚠️ الإقليم.** `config.js` → `REGION` = `me-central2` (الدمّام). **اجعله
إقليم Firestore نفسه**، وحدّث `REGION` في `account.html` و`start.js` بنفس القيمة.

## 🔴 لماذا لا يُرجع الويب-هوك ‎200 قبل المعالجة — لا تنقض هذا

شيفرة ‎2xx تقول لميسر «تسلّمتُ وعالجت» فتُلغي إعاداتها. وفي Cloud Functions
**لا يُضمَن تنفيذ عملٍ بعد إرسال الردّ**. فلو أجبنا ‎200 ثم ماتت المعالجة:
العميل دفع، ولا اشتراك، ولا إعادةَ تُنقذه. ومنطقنا قراءةٌ ومعاملة — عشرات
الميلي‑ثانية، لا مهلةَ تنتهي.

| الردّ | متى | الأثر عند ميسر |
|---|---|---|
| `2xx` | نتيجةٌ نهائية: فُعِّل · رُفض · مكرَّر | لا إعادة |
| `5xx` | عطلٌ عابر | **يُعيد** — وحارس `applied` يجعل الإعادة آمنة |
| `401` | رمزٌ سرّي خاطئ | مرفوضة |

## الاختبار — بلا شبكةٍ ولا مفتاحٍ ولا محاكٍ

```bash
node functions/test.js
```

يغطّي: الرمز السرّي · مطابقة الوضع · سُلّم الرفض · الإعادات المتكرّرة ·
التمديد التراكمي · جدول الباقات · منع البيع بلا سعر. **شغّله قبل كل نشر.**

## النشر

تلقائي عبر GitHub Actions — انظر `STACK.md`. ويدوياً:

```bash
firebase deploy --only firestore,functions:submitIntake
firebase deploy --only functions:createPayment,functions:moyasarWebhook   # بعد ضبط أسرار ميسر
```

## إعداد الويب-هوك في لوحة ميسر

`dashboard.moyasar.com ← Settings ← Webhooks ← Add`

| الحقل | القيمة |
|---|---|
| **Endpoint** | عنوان `moyasarWebhook` بعد النشر |
| **Secret Token** | نفس قيمة `MOYASAR_WEBHOOK_TOKEN` بالحرف |
| **HTTP Method** | `POST` |
| **Events** | `payment_paid` · `payment_faild` |

⚠️ **`payment_faild` هكذا بالضبط** — خطأٌ إملائيّ في توثيق ميسر.

⚠️ **ولا يُضبط `callback_url` في الفواتير عمدًا** — طريقُ إشعارٍ واحد: ويب-هوك اللوحة.

## الملفات

| الملف | الدور |
|---|---|
| `index.js` | نقطة الدخول — تهيئة Admin وتصدير الدوال |
| `config.js` | الأسرار والإقليم والأصل واشتقاق الوضع من المفتاح |
| `plans.js` | جدول الباقات — المصدر الوحيد للمبلغ والمدّة |
| `moyasar.js` | عميل ميسر — نقطة النهاية والمصادقة والحمولة |
| `createPayment.js` | الدالّة القابلة للنداء: `plan` ← رابط دفع |
| `webhook.js` | الويب-هوك: حدث الدفع ← `subscribed` و`subEndsAt` و`plan` |
| `verify.js` | القرارات الحسّاسة — وحدةٌ نقيّة مُختبَرة |
| `intake.js` | الدالّة القابلة للنداء: الاستمارة ← ملف صحي + أول وزن |
| `nutrition.js` | التحقق، Mifflin-St Jeor، الحد الأدنى، الفرز — وحدةٌ نقيّة مُختبَرة |
| `nutrition.config.json` | إعداد التغذية — يعدّله الأخصائي |
| `countries.json` | الدول العربية (السعودية أولاً) |
| `test.js` | الاختبارات |
